# Описание проекта: Управление Космическими Операциями

Наше приложение представляет собой систему для планирования и управления космическими миссиями. В данной ветке был произведен переход от монолитной архитектуры к микросервисному взаимодействию с использованием Docker и настроен процесс непрерывной интеграции (CI/CD).

## 🚀 Что было добавлено в рамках перехода на микросервисы

1. **Контейнеризация (Docker):**
   * Созданы раздельные `Dockerfile` для Сервера (`Dockerfile.server`) и Сервиса миссий (`Dockerfile.mission`).
   * Применена **многостадийная сборка (Multi-stage build)**: компиляция происходит внутри временного контейнера с использованием базового образа Gradle, а в финальный образ (Jre-alpine) копируется только готовый артефакт (JAR-файл или распакованные классы). Это существенно уменьшило вес образов.
   * Настроен запуск приложений от имени **непривилегированного пользователя** (`appuser`), что является стандартом безопасности (Security Best Practices).
   * Для сервиса миссий реализована распаковка fat-jar на этапе сборки для запуска планировщика без дублирования кода.

2. **Оркестрация (Docker Compose):**
   * Настроен файл `docker-compose.yml` для одновременного запуска двух сервисов.
   * Контейнеры объединены в изолированную пользовательскую сеть `space-network`, что позволяет им общаться по внутренним DNS-именам (например, `http://server:7070`).
   * Реализован **Healthcheck**: сервис миссий ожидает полной готовности сервера (проверка порта 7070) перед началом работы.
   * Конфигурация вынесена в **переменные окружения** (например, проброс портов и внешних секретов).

3. **CI/CD и Безопасность (GitHub Actions & Trivy):**
   * Разработан автоматический пайплайн `.github/workflows/ci-cd.yml`, который запускается при пуше в любую ветку или вручную.
   * Настроена интеграция скрытых переменных через **GitHub Secrets**.
   * Внедрены автоматические сканеры уязвимостей от **Trivy**:
     * **SAST** (Static Application Security Testing): Анализ исходного кода и Docker-файлов до сборки.
     * **DAST** (Dynamic/Image Scanning): Поиск уязвимостей в зависимостях уже собранного Docker-образа.

## 🛡️ Отчет по безопасности (По результатам сканирования Trivy)

Встроенный сканер безопасности проанализировал собранный образ сервера (`ext_course_1440-server:latest`) и выявил ряд уязвимостей в используемых зависимостях. 

**Сводка по Java-библиотекам (13 уязвимостей: 11 HIGH, 2 CRITICAL):**
Анализ `app.jar` показал, что текущая версия Spring Boot (3.4.2) тянет за собой уязвимые транзитные зависимости. Основные проблемные компоненты:
* **Apache Tomcat (10.1.34)** — обнаружено 10 уязвимостей (включая критическую *CVE-2025-24813*, связанную с риском удаленного выполнения кода и утечки данных через PUT-запросы, а также уязвимости, ведущие к отказу в обслуживании). Безопасные версии: `10.1.35` и выше.
* **Spring Boot (3.4.2)** — уязвимость *CVE-2025-22235* при работе с Actuator endpoints. Безопасная версия: `3.4.5`.
* **Spring Core (6.2.2)** — уязвимость *CVE-2025-41249* при детекции аннотаций. Безопасная версия: `6.2.11`.

**План по устранению:** Для устранения найденных уязвимостей необходимо обновить версию `org.springframework.boot` в файле `build.gradle.kts` с `3.4.2` до версии `3.4.5` (или новее). Обновление Spring Boot автоматически подтянет безопасные версии Tomcat (10.1.35+) и Spring Core (6.2.11+).

## 🛠️ Как запустить проект локально

1. Убедитесь, что у вас установлен Docker и плагин Docker Compose.
2. Перейдите в корневую директорию проекта.
3. Выполните команду для сборки и запуска контейнеров в фоновом режиме:
   ```bash
   docker compose up --build -d


4.  Для просмотра логов Сервиса миссий (клиента) выполните:
    ```bash
    docker compose logs -f mission-service
    ```
5.  Проверить доступность API сервера можно перейдя в браузере по адресу:
    [http://localhost:7070/swagger-ui.html](https://www.google.com/search?q=http://localhost:7070/swagger-ui.html)
6.  Для остановки и удаления контейнеров:
    ```bash
    docker compose down
    ```
