# 🛰️ Space Operation Center & Mission Scheduler

Проект представляет собой микросервисную архитектуру на базе Spring Boot для управления спутниковыми группировками и автоматизированного планирования космических миссий. 

Архитектура состоит из двух компонентов:
1. **Основной сервис (Space Operation Center)** — предоставляет REST API для управления спутниками и группировками.
2. **Сервис-планировщик (Mission Scheduler)** — микросервис, автоматически запускающий миссии по расписанию (Cron) через HTTP-запросы к основному сервису.

---

## 🛠 Технологический стек
* **Язык:** Java 21
* **Фреймворк:** Spring Boot 3.4+ (Web)
* **HTTP-клиент:** RestClient (Spring Boot 3.2+)
* **Документация API:** SpringDoc OpenAPI (Swagger UI)
* **Планировщик:** Spring Task Scheduler (`@EnableScheduling`)
* **Сборка:** Gradle

---

## 🚀 Основной сервис (REST API)

Сервис работает на порту `7070` (настраивается в `application.yml`) и отвечает за бизнес-логику управления космическими аппаратами.

### Документация API (Swagger UI)
Интерактивная документация ко всем эндпоинтам доступна в браузере после запуска приложения:
 **[http://localhost:7070/swagger-ui.html](http://localhost:7070/swagger-ui.html)**

### Основные Endpoints:
* `POST /api/add-satellites` — Добавление спутника в группировку. 
  *Поддерживает полиморфизм JSON для десериализации различных параметров спутников (Связь, ДЗЗ) с использованием аннотаций `@JsonTypeInfo` и `@JsonSubTypes`.*
* `POST /api/missions` — Выполнение миссии. Принимает DTO `MissionRequest`, поддерживает запуск как для всей группировки (`CONSTELLATION`), так и для одиночного спутника (`SINGLE_SATELLITE`).
* `GET /api/overview` — Получение текстовой сводки о текущем состоянии системы и всех группировок.
* `DELETE /api/constellations/{constellationName}/satellites/{satelliteName}` — Вывод конкретного спутника из эксплуатации.

## ⏱ Сервис-планировщик (Mission Scheduler)

Независимый микросервис (запускается на порту `8081`), не использующий базу данных. Все настройки и запланированные задачи живут в памяти и считываются из YAML-конфигурации при старте (`@PostConstruct`).

### Особенности реализации:
* Использует современный `RestClient` для отправки POST-запросов к основному API.
* Чтение конфигурации строго типизировано через `record` с аннотацией `@ConfigurationProperties`.
* Все HTTP-вызовы обернуты в обработчики исключений (try-catch), чтобы недоступность основного сервиса не приводила к падению планировщика.

### Конфигурация расписания
Настройки миссий задаются в `application.yml` планировщика. Используются стандартные Cron-выражения.

Пример конфигурации:
```yaml
server:
  port: 8081

app:
  space-center-service:
    url: "http://localhost:7070/api"
    missions:
      - targetType: CONSTELLATION
        constellationName: "GeoStationary"
        cron: "0 0 */6 * * *"  # каждые 6 часов
      - targetType: SINGLE_SATELLITE
        constellationName: "LowOrbit"
        satelliteName: "Sat-1"
        cron: "0 30 8 * * MON"  # каждый понедельник в 8:30
      - targetType: CONSTELLATION
        constellationName: "TestConstellation"
        cron: "0 */1 * * * *"   # каждую минуту
```

## ⚙️ Инструкция по запуску(вкладка services Intellij Idea)

1. **Запуск Основного API:**
   Запустите главный класс приложения (например, `Main.java`). Убедитесь, что сервис успешно стартовал на порту `7070` и Swagger UI доступен.
2. **Запуск Планировщика:**
   Параллельно запустите класс планировщика (порт `8081`).
   При старте в консоли планировщика будут залогированы все найденные миссии. В заданное по расписанию время планировщик автоматически отправит HTTP-запрос в основной сервис и выведет результат (успех или ошибку соединения). Работу миссий можно будет наблюдать в логах обоих приложений.
