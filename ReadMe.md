# Система Управления Космическими Операциями (Space Operations)

Данный проект представляет собой систему для планирования и управления космическими миссиями. В рамках развития проекта был произведен переход от монолитной архитектуры к микросервисной с использованием Docker, брокера сообщений Kafka и настроен процесс CI/CD.

##  Архитектура и инфраструктура
* **Контейнеризация:** Раздельные `Dockerfile` (многостадийная сборка) для основного `server` и планировщика `mission-service`. Запуск производится от непривилегированного пользователя (`appuser`).
* **Оркестрация:** Контейнеры (включая PostgreSQL и Kafka) объединены в `docker-compose.yml` в единую сеть `space-network` с настроенными Healthcheck.
* **Уязвимости (Security):** Выявлены и запланированы к устранению уязвимости базовых компонентов (Tomcat 10.1.34, Spring Boot 3.4.2). Планируется обновление до актуальных безопасных версий (Spring Boot 3.4.5+).
* **Логирование и конфигурация:** В проекте корректно настроены профили конфигурации (`application.yml`). Логирование выводится в стандартный поток с указанием времени, уровня (INFO/DEBUG), потока и класса, что позволяет эффективно отслеживать жизненный цикл бизнес-операций.

##  Нагрузочное тестирование (k6)
В рамках курса по системному дизайну для проекта разработаны нагрузочные тесты, проверяющие производительность ключевого бизнес-сценария.

###  Описание пользовательского сценария
Тестовый скрипт имитирует комбинированную работу оператора космического центра, выполняющего законченный бизнес-процесс:
1. **Получение общей сводки (GET `/api/overview`):** Оператор открывает дашборд и загружает актуальные данные о состоянии системы (операция чтения).
2. **Регистрация группировки (POST `/api/constellations`):** Оператор создает новую уникальную спутниковую группировку (операция создания/записи).
3. **Добавление спутника (POST `/api/add-satellites`):** В созданную группировку добавляется новый спутник типа `IMAGE` с заданными параметрами телеметрии (операция изменения).

###  Профиль нагрузки
* **Инструмент:** k6
* **Параллельные пользователи (VUs):** 20 (профиль адаптирован под возможности локального ПК и ограничения дефолтного пула соединений HikariCP/PostgreSQL).
* **Длительность:** 80 секунд непрерывной работы (20с плавный разгон, 40с удержание нагрузки, 20с спад).
* **Метрики (Thresholds):** Настроено ограничение на максимальный процент ошибок (`http_req_failed`).

## 🚀 Инструкция по запуску проекта и тестов

### 1. Запуск инфраструктуры и микросервисов
Убедитесь, что у вас установлен Docker. В корневой директории проекта выполните команду:
```bash
docker compose up -d --build

```

*Дождитесь, пока поднимутся все сервисы (`postgres`, `kafka`, `server`, `mission-service`). Главный API будет доступен на порту `7070`.*

### 2. Запуск нагрузочного тестирования

Убедитесь, что у вас установлена утилита **k6**. В корневой директории выполните:

```bash
k6 run k6/load-test.js

```

### 3. Просмотр графического отчета

В скрипт интегрирован визуальный HTML-репортер. После завершения теста (через 1 минуту 20 секунд) в корневой папке автоматически сгенерируется файл `load-test-report.html`.

Откройте `load-test-report.html` в любом веб-браузере, чтобы просмотреть дашборд с результатами (RPS, перцентили времени ответа, распределение успешных и проваленных проверок по каждому эндпоинту).
